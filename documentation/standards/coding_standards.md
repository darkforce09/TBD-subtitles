# Coding standards

The rules for the Rust code. A rule held by a program names the `cargo gates` gate or the test
that holds it; the rest are held in review.

## Language

- Rust only. Every tracked file is Rust, Markdown, TOML or JSON, apart from `Cargo.lock`, the git
  and editor configuration files, and subtitle fixtures under `tests/fixtures/`; no shell,
  Python, Node or Makefile, anywhere, for any purpose (`cargo gates language-bans`).
- Repository chores are Rust programs under `tools/`, run with `cargo run -p <tool>` or a cargo
  alias such as `cargo gates`.
- External programs: FFmpeg and ffprobe, run as child processes; the `claude` CLI as an optional
  language-model backend. Nothing else is run by the app. Repository tooling under `tools/` may
  also run `git` and `cargo`. Every child process goes through `crates/child_process/`.
- Models are downloaded already exported (ONNX, GGUF, safetensors) from pinned URLs with
  checksums; no code converts or exports models.

## Workspace

- One Cargo workspace, `resolver = "3"`, members listed explicitly.
- Every crate: `edition = "2024"`, `rust-version = "1.95"`, `publish = false`, a header comment
  saying what the crate is, and a comment on each dependency saying why it is there. Prefer
  `default-features = false` and enable only what is used.
- Lints: `cargo clippy --workspace --all-targets -- -D warnings`; formatting: `cargo fmt`.
- One `ort` version in the whole dependency tree; crates that bundle ggml each live in their own
  binary or worker process.

## Layering

- Product crates, lowest first: `job_model` and `child_process`; then `media_io`,
  `subtitle_formats` and `inference`; then `stages`; then `pipeline`; then the app
  `tbd_subtitles`. A crate depends only on crates of a lower layer, never a sibling; a tool
  depends only on the crates listed for it (`cargo gates crate-layering`, whose table is
  `tools/repo_gates/src/layout.rs`).
- Inside the app, `src/` holds `main.rs`, the composition modules `application/` and `cli/`,
  the shared `core/`, and one folder per feature with `mod.rs`, `models/`, `services/`, `ui/` and,
  when it returns events, `events.rs`. `models/` and `services/` never name egui or eframe; `ui/`
  draws from a borrowed view and returns events that the application applies after the frame;
  `core/` imports no feature; a feature never imports `application/`, `cli/` or another feature's
  `ui/` (the tests in `apps/tbd_subtitles/src/tests/architecture_rules.rs`).
- No flat dumps: group variants into subfolders (`crates/stages/src/alignment/`,
  `crates/inference/src/onnx/`).

## Files and tests

- Production files under 500 lines; test files under 1000 (`cargo gates file-length`).
- Tests live in a sibling folder: `#[cfg(test)] #[path = "tests/<file>.rs"] mod tests;`; no
  inline test module and no test function in a production file (`cargo gates test-placement`).
  Unit tests of a feature's models and services sit in `models/tests/` and `services/tests/`.
- Test fixtures sit beside their consumer in `tests/fixtures/`; audio and video fixtures are
  generated by the test or kept tiny.
- Tests that need the GPU or real models are marked `#[ignore]` with a reason and run explicitly.

## Comments

- Present tense; no history words, no ticket or milestone numbers (`cargo gates prose-rules`).
- Every crate root (`lib.rs`, `main.rs`) and every production file of 80 lines or more opens with
  a `//!` header naming, in order, **Role:** (what it does), **Position:** (who calls it, what it
  calls), **Signals and state:** (what it reads and writes) and **Invariants:** (what always
  holds) (`cargo gates module-headers`).
- Comment the why, not the what.

## Errors and processes

- Library crates return typed errors; the app reports them with context (`anyhow` at the top
  only).
- Never `unwrap()` or `expect()` on input from files, processes, models or the user.
- Every child process has a timeout and a cancellation path; its stderr is drained on its own
  thread; a killed job leaves its finished stages valid for resume.
- A check that could not run reports that it did not run; it never reports success.

## Whitespace

- UTF-8, LF line ends, a final newline, no trailing whitespace outside Markdown
  (`cargo gates editorconfig`, mirroring `.editorconfig`).

## Performance

- Stream media; never hold a whole 44.1 kHz track in memory.
- Load a model once per worker process and process every chunk of the job with it.
- Record every stage's duration and peak memory in the job report.
