# Coding standards

The rules for the Rust code, from the day the first crate lands. Rules marked *(gate)* are checked
by `tools/repo_gates`; rules marked *(test)* by an architecture test; the rest in review.

## Language

- Rust only. No tracked Python, shell, Makefile, Node or other script files, anywhere, for any
  purpose. *(gate)*
- Repository chores are Rust programs under `tools/`, run with `cargo run -p <tool>`.
- External programs: FFmpeg and ffprobe, run as child processes; the `claude` CLI as an optional
  language-model backend. Nothing else is shelled out to.
- Models are downloaded already exported (ONNX, GGUF, safetensors) from pinned URLs with
  checksums; no code converts or exports models.

## Workspace

- One Cargo workspace, `resolver = "3"`, members listed explicitly.
- Every crate: `edition = "2024"`, `rust-version = "1.95"`, `publish = false`, a header comment
  saying what the crate is, and a comment on each dependency saying why it is there. Prefer
  `default-features = false` and enable only what is used.
- Lints: `cargo clippy --workspace --all-targets -- -D warnings`; formatting: `cargo fmt`.
- One `ort` version in the whole dependency tree; crates that bundle ggml each live in their own
  binary or worker process.

## Layering

- `apps/tbd_subtitles` → `crates/pipeline` → `crates/stages` → `crates/inference`,
  `crates/media_io`, `crates/subtitle_formats` → `crates/job_model`. A crate never depends on one
  above it. *(test)*
- Inside the app, one folder per feature with `mod.rs`, `events.rs`, `models/`, `services/`,
  `ui/`, `tests/` and a README.md; shared code in `core/`. `models/` and `services/` never name
  egui; `ui/` draws from a borrowed view and returns events; a feature never imports another
  feature's `ui/`. *(test)*
- No flat dumps: group variants into subfolders (`stages/alignment/`, `inference/onnx/`).

## Files and tests

- Production files under 500 lines; test files under 1000. *(gate)*
- Tests live in a sibling file: `#[cfg(test)] #[path = "tests/<file>.rs"] mod tests;`.
- Test fixtures sit beside their consumer in `tests/fixtures/`; audio and video fixtures are
  generated by the test or kept tiny.
- Tests that need the GPU or real models are marked `#[ignore]` with a reason and run explicitly.

## Comments

- Present tense; no history, no ticket or milestone numbers.
- A non-trivial module opens with a `//!` header covering **Role** (what it does), **Position**
  (who calls it, what it calls), **Signals and state** (what it reads and writes), **Invariants**
  (what always holds).
- Comment the why, not the what.

## Errors and processes

- Library crates return typed errors (`thiserror`); the app reports them with context (`anyhow` at
  the top only).
- Never `unwrap()` or `expect()` on input from files, processes, models or the user.
- Every child process has a timeout and a cancellation path; its stderr is drained on its own
  thread; a killed job leaves its finished stages valid for resume.
- A check that could not run reports that it did not run; it never reports success.

## Performance

- Stream media; never hold a whole 44.1 kHz track in memory.
- Load a model once per worker process and process every chunk of the job with it.
- Record every stage's duration and peak memory in the job report.
